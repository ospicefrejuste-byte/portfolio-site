# ADEOYE — API et interface
Projet neuf dans /workspace/adeoye-ferme ; ne modifier aucun autre projet et ne pas réutiliser la base / les secrets du site scolaire.
Node 24, Express 5, async application, SQLite local et PostgreSQL cloud. Base vide par défaut, aucun compte / jeu de données réel généré.

## Rôles et sécurité
admin : tout, comptes et paramètres. manager : inventaire, élevage Goliath, dépenses, mouvements, notes ; consultation et exports. viewer : lecture et export seulement. Le propriétaire crée les comptes (la personne à distance viewer par défaut jusqu’à réponse). Sessions serveur cookie HttpOnly, SameSite=Lax, Secure production ; CSRF pour mutations authentifiées ; contrôle d’origine. Mot de passe minimum 12 caractères, scrypt, connexion limitée ; initial change obligatoire pour comptes créés. Pas de compte ou mot de passe par défaut. Aucun secret frontend.
JSON succès direct. Erreur {error}. Auth GET /api/auth/status => {initialized}; POST /api/auth/setup {token,username,password} => {user,csrf}; POST /api/auth/login {username,password} => {user,csrf}; GET /api/auth/me => {user,csrf}; POST /api/auth/logout {}; POST /api/auth/password {currentPassword,password} => {user,csrf}. user={id,username,role,mustChangePassword,enabled}. Mutations CSRF via X-CSRF-Token ; setup/login sans CSRF mais contrôle origine.

## Dépenses et achats
Table additive `adeoye_expenses`, RLS PostgreSQL, aucune remise à zéro de la base existante. admin et manager enregistrent ; viewer consulte et télécharge seulement. expense={id,description,category,supplier,amount,date,time,timezone,notes,createdAt,createdBy,reference}. Montant entier F CFA positif <=1000000000000 ; totaux cumulés exacts BigInt transmis sous forme de chaîne décimale. date YYYY-MM-DD valide, au plus tard aujourd’hui dans le fuseau de la ferme ; time HH:mm. timezone capture le fuseau des paramètres lors de l’enregistrement ; createdAt UTC donne la trace de saisie serveur. Description obligatoire max160, fournisseur facultatif max160, notes facultatives max2000. Catégories ['Aliments et intrants','Animaux','Cultures et récoltes','Matériel','Transport','Main-d’œuvre','Entretien','Autres'].
POST /api/expenses {requestId UUID,description,category,supplier,amount,date,time,notes}, CSRF et écriture requis, opération idempotente par utilisateur et payload ; conflit409 si UUID réutilisé pour une autre opération. Aucun effet automatique sur l’inventaire. Pas de modification ni suppression de dépenses enregistrées.
GET /api/state ajoute expenses triées date DESC,time DESC,createdAt DESC,id DESC. GET /api/expenses?from=YYYY-MM-DD&to=YYYY-MM-DD => {expenses,total,count,from,to}. Bornes facultatives et inclusives sur la date locale enregistrée ; bornes malformées ou inversées refusées. GET /api/reports/expenses.pdf utilise les mêmes filtres et permissions, produit un vrai PDF A4 paginé avec détails, dates, heures, références et total exact.
UI Dépenses et achats accessible à tous les comptes : filtre mois courant par défaut dans le fuseau ferme, période libre ou tout, total, historique et PDF de la période. Ajout réservé admin/manager, reprise durable des réponses incertaines réutilisant strictement UUID et payload de la dépense. Les champs de période en cours de saisie sont préservés des actualisations.

## Élevage Goliath
Tables additives `adeoye_goliath_batches` et `adeoye_goliath_events`, RLS PostgreSQL. Pas de lot fictif ni conversion automatique des anciennes fiches. Un nouvel arrivage est un lot indépendant et crée, dans la même transaction, un item `Animaux`, unité `tête`, et un mouvement opening. item.goliathBatchId identifie le lot lié. L’inventaire lié se gère uniquement via Goliath ; édition/archivage/mouvement manuels refusés409 pour préserver les effectifs.
Batch={id,itemId,reference,name,arrivalDate,hatchDate,initialCount,deadCount,soldCount,remainingCount,mortalityRate,ageDays,daysSinceArrival,stage,location,supplier,notes,version,createdAt,updatedAt,createdBy,salesTotal,unpricedSalesCount}. hatchDate/ageDays null si inconnus ; âge calculé en jours civils du fuseau de la ferme. Stades manuels `chicks`,`growing`,`adult`, aucun âge de maturité automatique. initialCount entier1..1000000000, remainingCount=initialCount-deadCount-soldCount. salesTotal chaîne décimale exacte BigInt ; les ventes sans prix sont signalées séparément.
POST /api/goliath/batches {requestId UUID,name<=160,arrivalDate,hatchDate facultative,initialCount,stage,location facultatif<=160,supplier facultatif<=160,notes facultatives<=2000}. PUT /api/goliath/batches/:id {version,name,stage,location,supplier,hatchDate,notes}, contrôle de version409 et immuabilité arrivée/effectif initial/compteurs. POST /api/goliath/batches/:id/events {requestId UUID,type:'mortality'|'sale',quantity,date,timeHH:mm,reason facultatif<=1000,buyer facultatif<=160,totalAmount facultatif null ou entier positif<=1000000000000 pour une vente}. Event={id,batchId,type,quantity,date,time,timezone,reason,buyer,totalAmount,remainingAfter,createdAt,createdBy,reference}. Dates valides sans futur, événement>=arrivée ; éclosion<=arrivée. Une mortalité crée loss, une vente exit ; enregistrement et compteurs sous la même transaction, sorties concurrentes sans effectif négatif. Création lot/événement idempotente UUID et payload lié à l’utilisateur, conflit409 si réutilisation pour autre opération. Pas de suppression de l’historique.
GET /api/goliath => {batches,events}. GET /api/state ajoute goliathBatches et goliathEvents. GET /api/reports/goliath.pdf?batchId UUID facultatif : PDF A4 du lot filtré ou de tous les lots, âge connu/inconnu, dates/événements/effectifs et recettes connues. Mutations admin/manager avec CSRF, lecture et PDF viewer autorisés. Aucune transaction de paiement ni dépense créée implicitement.
UI onglet Élevage Goliath, lots distincts, détail/historique, formulaires arrivée/mortalité/vente/stade, date/heure locales par défaut même à distance. Reprise durable avec UUID/payload conservés en cas de réponse incertaine pour lot et événement. Les recettes sont distinctes de la valeur estimée du stock ; les ventes non chiffrées n’apparaissent pas comme gratuites. Les achats restent dans Dépenses et achats.
