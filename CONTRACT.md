# ADEOYE — API et interface
Projet neuf dans /workspace/adeoye-ferme ; ne modifier aucun autre projet et ne pas réutiliser la base / les secrets du site scolaire.
Node 24, Express 5, async application, SQLite local et PostgreSQL cloud. Base vide par défaut, aucun compte / jeu de données réel généré.

## Rôles et sécurité
admin : tout, comptes et paramètres. manager : inventaire, mouvements, notes ; consultation et exports. viewer : lecture et export seulement. Le propriétaire crée les comptes (la personne à distance viewer par défaut jusqu’à réponse). Sessions serveur cookie HttpOnly, SameSite=Lax, Secure production ; CSRF pour mutations authentifiées ; contrôle d’origine. Mot de passe minimum 12 caractères, scrypt, connexion limitée ; initial change obligatoire pour comptes créés. Pas de compte ou mot de passe par défaut. Aucun secret frontend.
JSON succès direct. Erreur {error}. Auth GET /api/auth/status => {initialized}; POST /api/auth/setup {token,username,password} => {user,csrf}; POST /api/auth/login {username,password} => {user,csrf}; GET /api/auth/me => {user,csrf}; POST /api/auth/logout {}; POST /api/auth/password {currentPassword,password} => {user,csrf}. user={id,username,role,mustChangePassword,enabled}. Mutations CSRF via X-CSRF-Token ; setup/login sans CSRF mais contrôle origine.

## Données
GET /api/settings public => {name:'Ferme ADEOYE',description,location:'',currency:'XOF',timezone:'Africa/Porto-Novo'} ; PUT admin même objet sauf currency fixe XOF (F CFA interface). Ne pas inventer adresse, propriétaire ou produit de ferme.
GET /api/state auth => {items,movements,notes,settings,updatedAt}; limité au compte connecté, aucun mot de passe / token exposé. items/movements/notes triés récent. Quantités >=0 à 3 décimales max (unités dénombrables tête/pièce/plateau entières) ; argent entier F CFA >=0.
item={id,name,category,unit,location,quantity,minQuantity,unitValue,notes,active,version,createdAt,updatedAt}. Catégories exactement ['Animaux','Cultures et récoltes','Aliments et intrants','Matériel','Autres']. unit custom string max24; units conseillées tête,kg,sac,pièce,litre,tonne,plateau,unité. POST /api/items {name,category,unit,location,quantity,minQuantity,unitValue,notes,requestId UUID}; stock initial consigné movement opening, idem retries. PUT /api/items/:id {name,category,location,minQuantity,unitValue,notes,version}; ne pas modifier unité/quantité hors mouvements. POST /api/items/:id/archive {version}; uniquement stock zéro, historique préservé, conflit409. Pas de suppression destructive.
movement={id,itemId,itemName,unit,type,quantity,balanceAfter,reason,date,createdAt,createdBy,reference}; types entry,exit,loss,opening. POST /api/movements {requestId UUID,itemId,type,quantity,reason,date}; date YYYY-MM-DD valide passée ou aujourd’hui (UTC) ; type entry,exit,loss ; quantité >0 ; raison obligatoire ; quantité sortie/perte <=stock sous transaction ; idempotent même UUID+payload, conflit409 si différents ; création avec l'identifiant requête. Aucun update/suppression de mouvement.
note={id,title,body,date,createdAt,createdBy}; POST /api/notes {title,body,date}. Notes de terrain, lecture pour tous.
GET /api/users admin => {users}; POST /api/users {username,password,role} => user (mustChangePassword true); PATCH /api/users/:id {enabled} pas désactivation soi/dernieradmin ; POST /api/users/:id/reset-password {password} revoke sessions + changement obligatoire.
GET /api/export/inventory.csv et /api/export/movements.csv auth : CSV UTF8 BOM ; colonnesFR et anti-injection formule.
GET /api/reports/inventory.pdf auth : vrai PDF A4, noms, catégorie, quantité unité emplacement, seuil, valeur estimée, date.
GET /api/health => {ok:true} (ne divulguepasconfig)

## Dépenses et achats
Table additive `adeoye_expenses`, RLS PostgreSQL, aucune remise à zéro de la base existante. admin et manager enregistrent ; viewer consulte et télécharge seulement. expense={id,description,category,supplier,amount,date,time,timezone,notes,createdAt,createdBy,reference}. Montant entier F CFA positif <=1000000000000 ; totaux cumulés exacts BigInt transmis sous forme de chaîne décimale. date YYYY-MM-DD valide, au plus tard aujourd’hui dans le fuseau de la ferme ; time HH:mm. timezone capture le fuseau des paramètres lors de l’enregistrement ; createdAt UTC donne la trace de saisie serveur. Description obligatoire max160, fournisseur facultatif max160, notes facultatives max2000. Catégories ['Aliments et intrants','Animaux','Cultures et récoltes','Matériel','Transport','Main-d’œuvre','Entretien','Autres'].
POST /api/expenses {requestId UUID,description,category,supplier,amount,date,time,notes}, CSRF et écriture requis, opération idempotente par utilisateur et payload ; conflit409 si UUID réutilisé pour une autre opération. Aucun effet automatique sur l’inventaire. Pas de modification ni suppression de dépenses enregistrées.
GET /api/state ajoute expenses triées date DESC,time DESC,createdAt DESC,id DESC. GET /api/expenses?from=YYYY-MM-DD&to=YYYY-MM-DD => {expenses,total,count,from,to}. Bornes facultatives et inclusives sur la date locale enregistrée ; bornes malformées ou inversées refusées. GET /api/reports/expenses.pdf utilise les mêmes filtres et permissions, produit un vrai PDF A4 paginé avec détails, dates, heures, références et total exact.
UI Dépenses et achats accessible à tous les comptes : filtre mois courant par défaut dans le fuseau ferme, période libre ou tout, total, historique et PDF de la période. Ajout réservé admin/manager, reprise durable des réponses incertaines réutilisant strictement UUID et payload de la dépense. Les champs de période en cours de saisie sont préservés des actualisations.
